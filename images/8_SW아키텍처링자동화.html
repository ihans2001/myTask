SW 아키텍처링 자동화

SSoT SW BOM에서 아키텍처링에 필요한 표를 추출해, 정적·동적 다이어그램과 SW 아키텍처링 명세서(워드)까지 자동으로 만든다. 신호흐름·고장전파·고장모드를 함께 표현하는 새로운 시퀀스 다이어그램이 핵심이다.
SSoT 연계 정적+동적 다이어그램 자동생성 명세서(워드) 자동생성
01왜 필요한가
다이어그램을 전부 수작업으로 작성
상용 모델링 툴로 한 장 한 장 그리는 데 막대한 시간(MH)이 투입된다
구조가 바뀌면 다이어그램만 남겨짐
설계가 바뀌어도 다이어그램을 매번 다시 그리지 않아 명세서와 실제 구조가 어긋난다
고장 정보는 별도로 그려야 함
신호흐름과 고장전파·고장모드를 한 장에 담는 다이어그램은 수작업으로는 만들기 특히 어렵다
아키텍처링과 문서화가 따로 진행
표로 정리한 내용을 다시 문서 형식으로 옮겨 적는 이중 작업이 반복된다
02무엇을 만드는가
①
SW 아키텍처링 테이블
SSoT SW BOM에서 아키텍처링에 필요한 열만 추출한 원장
②
정적 다이어그램 자동생성
계층구조·컴포넌트 분할·인터페이스 다이어그램을 표에서 바로 산출
③
New 시퀀스 다이어그램 자동생성
신호흐름·고장전파·고장모드까지 표현하는 확장형 시퀀스 다이어그램
④
SW 아키텍처링 명세서(워드) 자동생성
표와 다이어그램을 문서 서식에 맞춰 자동으로 삽입
핵심 기술
AST 파서(구조 정보 추출) PlantUML(시퀀스 다이어그램) VBA-Python 브릿지
기존 방식과 차이
기존: Enterprise Architect 등으로 수기 작성 → 막대한 MH 신규: 테이블만 채우면 다이어그램·문서가 자동 산출
03동작 흐름
1
테이블 추출
SSoT SW BOM에서 아키텍처링에 필요한 행·열만 추출한다
2
정렬·그룹화
계층·순서 기준으로 데이터를 정리한다
3
구조 분석(AST 파서)
코드 구조를 분석해 시퀀스에 필요한 신호·흐름 정보를 뽑아낸다
4
다이어그램 렌더링
PlantUML 등으로 정적·동적 다이어그램을 그림 파일로 생성한다
5
명세서 자동 삽입
표와 다이어그램을 워드 명세서 서식에 자동으로 채워 넣는다
04무엇이 새로운가 — 시퀀스 다이어그램
기존
메시지 순서만 표현
누가 언제 무엇을 호출하는지, 실행 순서만 보여준다. 고장이 발생했을 때 무슨 일이 벌어지는지는 별도 자료를 찾아야 한다.
신규(New)
신호흐름 + 고장전파 + 고장모드
정상적인 신호흐름은 물론, 특정 지점에서 고장이 발생했을 때 그 영향이 어디까지 전파되는지, 어떤 고장모드로 나타나는지까지 한 장에 표현한다.
05자동 생성되는 다이어그램 종류
정적계층구조 다이어그램
정적컴포넌트 분할 다이어그램
정적인터페이스 다이어그램
동적데이터흐름 다이어그램
동적태스크 스케줄링 다이어그램
동적시퀀스 다이어그램(신호흐름·고장전파·고장모드)
구조가 바뀌면 다이어그램도 함께 바뀐다 — 정적 아키텍처(SSoT)가 갱신되면 다이어그램이 자동으로 다시 생성되므로, 명세서와 실제 구조가 어긋나는 문제가 구조적으로 줄어든다.
06기대 효과
수작업 공수 대폭 절감
상용 툴로 한 장씩 그리던 다이어그램을 자동으로 생성한다
구조 변경에 즉시 대응
SSoT만 고치면 다이어그램과 명세서가 함께 갱신된다
고장 정보를 한 장으로
신호흐름과 고장전파·고장모드를 하나의 다이어그램에서 함께 확인한다
명세서 작성 시간 단축
표와 다이어그램이 문서에 자동으로 삽입되어 이중 작업이 사라진다
07유의할 점
  • 자동 생성된 다이어그램도 최종 검토는 엔지니어가 수행해야 한다
  • 소스 코드 구조가 바뀌면 재추출이 필요하다
  • 상용 모델링 툴 없이도 동작하지만, 대규모 협업 모델링에는 상용 툴이 유리한 경우도 있다
