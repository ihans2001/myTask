트래커 자동화 (RAG 오토링크+정합성 검증)

ALM(Codebeamer)은 공식 저장소·승인 창구로 유지하고, 트래커 초안 생성·오토 링크 추천·정합성 검증은 로컬 파이프라인에서 자동화한다. V-Cycle 전 구간(SR→SYS→SW→SWDD)에 걸쳐 반복 적용된다.
JSON 마스터+Excel On-demand 뷰 RAG Top-K 오토링크 추천 Orphan/Drift/Diamond 반복검증
01왜 필요한가
수백~수천 항목 추적성을 수작업으로
ALM에서 양방향 추적성을 수작업으로 맺으면 공수와 휴먼에러(누락·오매칭)가 계속 발생한다
기존 산출물이 있어도 매번 처음부터 작성
과거 검증된 설계서·코드가 있는데도 트래커를 매번 수기로 새로 쓴다
신구 요구조건 차이를 놓치기 쉬움
요구조건이 바뀌었는지, 어디가 바뀌었는지 일일이 대조하기 어렵다
링크를 맺은 뒤에도 결함이 남을 수 있음
고립된 항목이나 시점이 어긋난 연결을 사후에 걸러낼 방법이 없다
02무엇을 만드는가
①
레거시 활용 하위 트래커 초안 생성
과거 프로젝트의 SYS_SSoT/SWDD 등을 컨텍스트로 LLM이 하위 트래커 뼈대를 초안 작성한다
②
신구 요구조건 Delta 분석
Added/Deleted/Modified/Unchanged 4가지 상태로 신구 요구조건 차이를 자동 분류한다
③
RAG 기반 오토 링크 추천
리프 노드 임베딩과 코사인 유사도로 상위-하위 항목의 Top-K 후보를 추천한다
④
Orphan/Drift/Diamond 반복 검증
고립·시점불일치·다중소유 3대 결함을 그래프로 순회 탐지하고 오류 0건까지 반복한다
핵심 원리
JSON을 상시 마스터로 두고, 검토·확정 시에만 json_to_excel/excel_to_json으로 왕복 동기화(Round-trip)
번호체계 예외
산문 요구사항·번호 중복·번호 건너뜀 등 9종 이상 케이스를 명시적 폴백+품질이슈 로그로 기록
03어떻게 동작하는가
1
실데이터 연동·번호체계 정제
ALM에서 트래커를 읽기전용으로 Export해 표준 SSoT로 변환하고 번호체계 이상을 폴백 처리한다
2
하위 트래커 초안+Delta 분석
레거시 산출물로 LLM이 초안을 작성하고 신구 요구조건 차이를 함께 도출한다
3
Excel On-demand 검토
json_to_excel로 Draft_Sub_Tracker.xlsx/Delta_Report.xlsx를 열어 사람이 검토한다
4
RAG 오토 링크 추천
임베딩·벡터 검색으로 상위-하위 후보를 Top-K로 추천해 Link_Suggestions 시트에 반영한다
5
승인·정합성 반복 검증
드롭다운으로 승인/반려하면 VBA가 UpstreamID를 자동 매핑하고, Orphan/Drift/Diamond를 오류 0건까지 반복 검증한다
6
JSON 역동기화
검토·승인이 끝난 엑셀 내용을 excel_to_json으로 SSoT 마스터에 다시 반영한다
04ALM vs 로컬 지원 파이프라인 역할 분담
구분
ALM (Codebeamer)
로컬/서버 지원 파이프라인 (이번)
역할
공식 저장·동료검토·최종 승인·감사
트래커 초안·오토링크·정합성 진단
데이터 형태
공식 트래커 (승인본)
JSON 마스터 + On-demand Excel 뷰
반복 여부
승인 시점에 1회 확정
오류 0건이 될 때까지 반복 검증
사람 개입 시점
동료검토·최종 승인
초안 검토, 오토링크 승인/반려, 본문 수정
무거운 RAG 연산·임베딩·정합성 진단은 전부 로컬/서버에서 수행해, 엔지니어의 수작업 피로도를 제로화하는 것이 설계 철학이다.
05Before / After
이전 — 추적성을 전부 수작업으로
결함을 사후에 걸러낼 방법 없음
트래커 작성부터 링크 매칭까지 전부 사람이 맺고, 결함이 남아도 사후에 걸러낼 방법이 없었다.
현재 — 초안·추천·검증을 자동화
오류 0건까지 반복 검증
레거시 기반 초안과 RAG 추천으로 링크를 제안받고, Orphan/Drift/Diamond를 오류 0건까지 반복 검증한다.
06기대 효과
수작업 피로도 제로화
무거운 연산과 정합성 진단을 로컬/서버 파이프라인이 전담한다
검증된 자산 재사용
과거 프로젝트 산출물을 초안 작성에 활용해 개발 리스크·중복 투자를 줄인다
감사 대응력 향상
사후 탐지 진단과 검토 이력이 축적되어 ASPICE/ISO26262/21434 감사에 대응한다
V-Cycle 전 구간 확장 가능
시트 파라미터만 바꾸면 SR→SYS→SW→SWDD 전 구간에 같은 체계를 적용한다
07유의할 점
  • 파이썬 함수 20여 개 중 대부분은 이전 태스크에서 이미 검증되었으나, 엑셀→ALM 트래커 임포트 기능은 아직 미검증 상태다(코드비머의 공식 엑셀 임포트 로직을 적용 예정)
  • 애매한 번호체계 케이스는 그럴듯하게 추정하지 않고 항상 명시적 폴백으로 떨어뜨려 품질이슈 로그에 남긴다
  • 첫 실데이터 적용 범위는 CR 1~2건, 1개 인접 체인으로 축소해 착수하며, 전 구간 확장은 이후 단계에서 진행한다
