MITRE CVE 월간(또는 주간) 모니터링

매일 자동 실행되는 monthMonitoring 체계가 구조적으로 놓치는 "지연 공개 CVE"를, MITRE 저장소의 zip 스냅샷 델타(delta) 정보로 주기적으로 보완한다. 자동 추출된 결과는 dayMonitoring과 유사한 필드로 별도 raw 파일에 기록된다.
zip 부분추출(전체 압축해제 없음) delta+baseline 합집합 탐지 Repository_ID 읽기전용 대조
01왜 필요한가
번호 기반 탐지는 지연공개 CVE를 놓침
baseline보다 항상 작은 번호로 남는 CVE는 매일 모니터링에서 영구히 감지되지 않는다
기존 재스윕은 처리시간이 너무 김
main.zip 전체 압축해제에 수 시간이 걸렸다
두 체계의 데이터 형식이 달랐음
개별 CVE별 xlsx와 가변 컬럼 구조라 monthMonitoring의 고정 스키마와 호환되지 않았다
중복 CVE 체크 로직이 없었음
이미 저장소에 있는 CVE가 다시 섞여 들어올 수 있었다
02무엇을 만드는가
①
zip 부분 추출
main.zip을 통째로 풀지 않고 delta.json/deltalog.json과 실제 변경 CVE만 메모리에서 직접 읽는다
②
delta+baseline 합집합 탐지
delta 목록과 직전 baseline보다 큰 번호를 모두 모아 사각지대를 서로 보완한다
③
dayMonitoring과 동일한 필드로 rawData 생성
resweep_yymmdd.xlsx를 monthMonitoring!Repository_ID와 같은 고정 B~S 스키마로 만든다
④
Audit 대비 저장 옵션
자동 추출된 원본 CVE json을 실적 증적용으로 저장할지 옵션으로 선택한다
핵심 원리
monthMonitoring.xlsm은 xlwings로 읽기 전용 대조만 하고 절대 저장하지 않아 손상을 방지
사각지대 보완
deltaLog.json은 최근 30일치만 롤링 보관 → 30일 넘긴 다운로드 공백은 baseline 번호 스캔으로 보완
03어떻게 동작하는가
1
zip 목차만 조회
main.zip을 열고 namelist()로 목차만 읽어 압축을 풀지 않는다
2
delta 변경목록 추출
delta.json/deltalog.json을 메모리에서 읽어 변경된 CVE ID 집합을 구한다
3
baseline 이후 번호 합집합
직전 baseline보다 큰 번호를 zip 목차에서 스캔해 delta 목록과 합친다
4
기존 저장소 대조
Repository_ID를 읽기 전용으로 조회해 이미 등록된 CVE를 제외한다
5
동일 규칙으로 필드 파싱
dayMonitoring의 파싱 로직과 같은 규칙으로 CWE/CVSS/Vendor 등을 파싱한다
6
rawData 저장 및 반영
resweep_yymmdd.xlsx로 저장한 뒤 monthMonitoring.xlsm에 반영하고 이후는 dayMonitoring과 동일하게 분석한다
04일일 모니터링 vs 델타 재스윕
구분
monthMonitoring (일일 모니터링)
mitre_delta_resweep (재스윕)
실행 주기
매일 (스케줄러 자동)
비정기 (zip 수동 다운로드 시, 월~2개월)
탐지 방식
키워드 검색+baseline 번호 비교, 조기중단
delta 변경목록 ∪ baseline 번호 스캔 (합집합)
주요 사각지대
번호가 baseline보다 작은 지연공개 CVE를 영구히 놓침
delta 자체 사각지대(30일 롤링 한계)는 baseline 스캔으로 보완
monthMonitoring 접근
직접 열어 읽기+쓰기 후 매크로 호출
읽기 전용으로만 열람, 쓰기·저장 없음
두 체계는 서로 대체 관계가 아니라 상호보완 관계로 설계되었다 — 각자 놓치는 사각지대를 서로 상쇄한다.
05Before / After
이전 — 수 시간짜리 전체 압축해제
형식도 달라 그대로 반영 불가
main.zip을 통째로 풀어야 했고, 결과물 형식도 monthMonitoring과 달라 그대로 반영할 수 없었다.
현재 — 수 분 내 부분추출+동일 스키마
같은 필드의 rawData로 바로 반영
필요한 파일만 부분 추출해 수 분 내 처리하고, dayMonitoring과 같은 필드의 rawData로 바로 반영한다.
06기대 효과
처리시간 대폭 단축
main.zip 처리시간을 수 시간에서 수 분 이내로 줄인다
탐지 완전성 향상
번호 기반과 delta 기반, 두 탐지 방식의 사각지대를 서로 보완한다
데이터 정합성 확보
동일한 필드 파싱 규칙과 출력 스키마로 두 체계 간 형식을 통일한다
파일 손상 위험 차단
monthMonitoring.xlsm을 읽기 전용으로만 대조해 손상 위험을 원천 차단한다
07유의할 점
  • main.zip 다운로드 자체는 자동화되어 있지 않으며(수동 다운로드 후 스크립트 실행), Resweep_ID 스테이징 결과를 Repository_ID로 병합하는 과정도 수동 검토가 전제된다
  • Triage/Trigger(벤더·키워드) 자동 분류는 이 스크립트의 책임 범위 밖이며, 후속 필터링 단계에서 진행할 예정이다
  • xlwings 특성상 실행 PC에 Excel이 설치·구동 가능해야 하며, 실제 monthMonitoring.xlsm을 이용한 최종 통합 검증은 Windows+Excel 운영 PC에서 확인이 필요하다
