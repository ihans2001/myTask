IHANS-PRO-2026-014 2026-09-09 제안서

사이버보안 취약점(CVE) 자동 모니터링

담당 키워드의 신규 취약점을 정해진 시각에 자동으로 찾아 기록하고, 기존 엑셀·VBA 관련도 평가 체계와 그대로 연동한다. SW BOM과 연계하면 오픈소스 구성요소로 범위를 좁힌 모니터링도 가능하다.
일간·월간 모두 지원 VBA-Python 브릿지 SBOM 연계 확장 가능
01왜 필요한가
매일 수작업 검색은 부담이 큼
120개 이상의 키워드를 매일 하나하나 검색·정리하려면 시간이 많이 든다
사람이 하면 누락되기 쉬움
반복 작업일수록 놓치거나 늦어지는 위험이 커진다
CRA 규제로 SBOM 중요성 확대
오픈소스 구성요소의 취약점을 지속적으로 추적해야 하는 요구가 강화된다
며칠만 밀려도 따라잡기 어려움
출장·휴가로 실행이 밀리면 그 사이 쌓인 항목을 수작업으로 확인하기 힘들다
02무엇을 만드는가
①
자동 검색·기록 에이전트
담당 키워드별 신규 취약점을 자동으로 찾아 표준 형식으로 기록
②
기존 엑셀·VBA 체계와 연동
새로 만들지 않고 기존 관련도 평가 매크로를 그대로 호출
③
일간/월간 실행 모두 지원
매일 정해진 시각 또는 주기적(월간) 실행 방식을 선택 가능
④
백로그 자동 추적
실행이 며칠 밀려도 그 사이 쌓인 신규 항목을 누락 없이 따라잡음
핵심 구조 — VBA-Python 브릿지
엑셀(VBA)이 데이터 원본(SSoT) Python이 검색·수집을 담당하는 연산 엔진
실행 방식
윈도우 작업 스케줄러로 매일 정해진 시각 자동 실행(일간) 필요 시 주기적(월간) 검색으로 전환 가능
03어떻게 동작하는가
1
키워드 순회
담당 키워드마다 최신 취약점 목록을 검색한다
2
신규 여부 판별
직전 실행 때 저장해둔 마지막 항목을 만나면 즉시 확인을 멈춘다
3
상세 정보 수집
신규 항목이 있으면 상세 정보를 모두 채운다
4
기존 매크로 호출
저장 완료 후 기존 관련도 평가 매크로를 자동 실행한다
04핵심 최적화 — 조기 중단(Early-Stop)
검색결과가 항상 최신순으로 정렬된다는 점을 이용해, 직전 실행 때의 마지막 확인 지점을 만나는 즉시 멈춘다. 실행이 며칠 밀려도 페이지당 표시 건수를 넉넉히 잡아 페이지 전환 횟수를 최소화하면서, 평소에는 여전히 빠르게 끝난다.
약 16분
평소(전일 대비 소량 신규) — 검색+상세수집 합계
약 38분
1~2주 미실행 후(백로그 발생) — 검색+상세수집 합계
05SBOM 연계 — 오픈소스 모니터링 범위 좁히기
CRA(사이버복원력법) 규제 강화로 SBOM(소프트웨어 구성요소 목록)의 중요성이 커지고 있다. 이 모니터링 로직은 SW BOM과 연계하면, 담당자가 정한 전체 키워드가 아니라 실제 사용 중인 오픈소스 구성요소만으로 검색 범위를 좁혀 수행할 수 있다 — 관련 없는 검색을 줄이고, 우리 제품에 실제로 영향을 주는 취약점에 집중한다.

09실전에서 얻은 일반 원칙
실제 구현 과정에서, 화면을 흉내 내어 데이터를 긁어오던 방식을 공식 API 직접 호출 방식으로 전환한 경험이 있다. 이는 이번 도구에 국한되지 않고, 다른 웹 자동화 작업에도 그대로 적용할 수 있는 점검 순서다.
  1. 화면에 보이는 정보는 반드시 어딘가의 API 응답에서 온다 — 원본 요청을 먼저 찾아본다
  2. 'View JSON', 'Export', 'API' 같은 링크나 버튼이 있는지 가장 먼저 확인한다
  3. 고정된 포맷을 가진 값은 화면 구조가 아니라 정규식으로 직접 추출하는 편이 더 견고하다
  4. 브라우저 자동화는 '공식 API가 없을 때의 최후 수단'으로 남겨둔다
