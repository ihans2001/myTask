JIRA 프로젝트 현황관리 자동화

조직 바운더리(전사/연구소/센터·실/팀/그룹) 안의 모든 프로젝트 현황을 자동 집계한다. 보직자는 주관·참여 프로젝트만 권한에 따라 차별화해서 보고받고, 지정된 담당자의 트리거에 따라 자동 분류되어 메일로 발송된다.
조직 트리 롤업 리스크 2축(일정/기술 × 정적/동적) 트리거 기반 자동 메일발송
01왜 필요한가
조직 경계마다 현황을 따로 취합
전사/연구소/센터·실/팀/그룹 등 여러 레벨에서 각자 현황을 취합하면 중복 작업이 생긴다
보직자마다 봐야 할 범위가 다름
모두에게 같은 정보를 주면 정작 필요한 담당 범위가 묻힌다
변화만 짚어내기 어려움
이슈가 많아지면 이번 주에 실제로 뭐가 바뀌었는지 찾기 어렵다
정체·악화 신호를 놓치기 쉬움
마감 지연이나 우선순위 상향 같은 신호는 여러 주 이력을 봐야 드러난다
02무엇을 만드는가
①
조직 바운더리별 자동 롤업
전사~그룹까지 조직 트리를 재귀 순회해 각 노드의 담당·참여 프로젝트를 자동 집계한다
②
보직자 권한별 차등 보고
주관(main)·참여(participating) 프로젝트만 해당 보직자에게 보이도록 범위를 제한한다
③
리스크 2축 자동 분류
일정/기술 축을 정적·동적 기준으로 나눠 리스크 이슈를 자동으로 식별한다
④
트리거 기반 자동 메일 발송
지정된 담당자의 실행 트리거에 따라 보직자별 파일이 자동 분류되어 메일로 발송된다
핵심 원리
같은 프로젝트라도 조직 트리 어느 가지에 있든 main/participating 매칭으로 상위까지 롤업
확장 계획
이슈 설명·이력 텍스트에 LLM 기반 tone & manner 분석을 더해 리스크 판정 보강 예정
03어떻게 동작하는가
1
현재 상태 조회
JIRA에서 상태/담당자/마감일/우선순위를 조회해 curr 스냅샷을 만든다
2
필드 diff 계산
전주(prev)와 금주(curr)를 비교해 이슈별 변경 필드를 골라낸다
3
이력 누적
매주 스냅샷을 이력 저장소에 쌓아 몇 주째 정체인지 재구성할 수 있게 한다
4
리스크뷰 산출
일정/기술 × 정적/동적 2축 규칙으로 프로젝트별 리스크 이슈를 골라낸다
5
조직 롤업 및 파일 분류
조직 트리를 순회해 보직자별 주관/참여 프로젝트 파일을 작성한다
6
트리거 실행 및 메일 발송
담당자가 실행하면 보직자별 파일이 자동 분류되어 메일로 발송된다
04개발 진입점 vs 운영 진입점
구분
main.py / main_comprehensive.py (개발)
real_run.py (운영, ★ 트리거)
스냅샷 출처
mock JSON 파일 2~6주치
prev=이력 저장소 최근값, curr=JIRA 실시간 조회
메일 발송
dry_run=True 고정(발송 계획만 생성)
send_mail 옵션으로 실제 Outlook 발송 가능
검증 방식
리스크 케이스별 OK/FAIL 자동 비교
실 운영 환경(로컬 Windows+Outlook)에서 실행
diff_core/project_aggregate/org_rollup/risk_rules/risk_aggregate/export_excel/mailer는 mock과 실운영에서 전혀 수정 없이 그대로 재사용된다 — "스냅샷을 어디서 가져오는가"만 바뀐다.
05Before / After
이전 — 조직마다 개별 취합
모두에게 같은 범위로 보고
여러 조직 레벨에서 각자 현황을 취합하고, 모두에게 같은 범위의 정보를 보고했다.
현재 — 바운더리별 자동 롤업+차등 발송
권한 범위만 골라 자동 발송
조직 트리를 자동 순회해 보직자의 주관·참여 범위만 골라 리스크와 함께 메일로 자동 발송한다.
06기대 효과
보고 범위 최적화
보직자마다 주관·참여 프로젝트만 골라 보여 불필요한 정보를 줄인다
리스크 조기 포착
일정/기술 2축 규칙으로 정체·악화 신호를 자동으로 찾아낸다
반복 작업 자동화
트리거 실행만으로 집계부터 메일 발송까지 이어진다
조직 변경에 유연
조직 트리와 프로젝트 매핑만 바꾸면 어떤 바운더리 구조에도 적용된다
07유의할 점
  • 실제 발송은 로컬 Windows + Outlook 데스크톱 앱 환경에서만 가능하며, send_mail=False가 기본값으로 먼저 결과를 확인한 뒤 발송해야 한다
  • 삭제된 이슈는 조용히 빠지지 않고 DELETED로 명시적으로 남겨, 이슈가 사라진 사실 자체를 놓치지 않게 한다
  • LLM 기반 tone & manner 분석은 아직 규칙 기반(일정/기술 2축) 리스크 판정만 구현되어 있으며, 향후 확장 예정이다
