SW 테스트케이스 설계 (LLM+AST 기반, Mode B)

MBD(Ascet/Simulink 등)에서 자동 생성됐거나 수기로 작성한 펌웨어 탑재용 최종 코드를 AST로 파싱해, 코드 단위 최소 테스트케이스를 제안한다. 함수 정의는 설계 템플릿과 공용이지만 결과는 별도 파일에 기록해 V-Cycle 검증 산출물로 남긴다.
libclang 기반 실제 AST 파싱 Full_Match/Missing/Unspecified 판정 설계단계 TC(draft)와 상호비교
01왜 필요한가
최종 코드 기준 검증 근거가 없음
설계 단계 코드가 아니라 펌웨어에 실제 탑재되는 최종 코드를 기준으로 검증해야 한다
LLM 코드 해석만으로는 한계
설계 단계(Mode A)의 LLM 직접 해석 방식은 코드 규모가 커지면 정확도가 떨어질 수 있다
설계와 검증 산출물이 뒤섞이면 곤란
같은 파일에 설계 정보와 검증 결과가 섞이면 V-Cycle 상 산출물 구분이 애매해진다
설계 단계 TC가 적정한지 확인할 방법이 없음
설계 초안 테스트케이스만으로는 그것이 충분한지 검증할 기준이 없다
02무엇을 만드는가
①
libclang 기반 실제 AST 파싱
MBD 자동생성 또는 수기 작성된 최종 C 코드의 조건분기·전역/정적 변수 수정을 정적으로 추출한다
②
코드 단위 최소 테스트케이스 제안
조건분기를 근거로 SW 검증에 필요한 최소한의 테스트케이스를 도출한다
③
설계-검증 파일 분리
함수 정의는 설계 템플릿과 공용으로 쓰되, 테스트케이스 결과는 검증 전용 파일에 별도로 기록한다
④
설계단계 TC(draft)와 상호비교
Mode A(설계) 단계에서 나온 TC 초안과 Mode B(검증) 결과를 대조해 적정성을 점검한다
핵심 원리
Black-box(요구사항 기반)와 White-box(AST 기반) TC를 각각 도출 후 Full_Match/Missing/Unspecified 3단계 판정
파일 분리 원칙
검증 전용 파일은 VBA 매크로가 아예 없는 순수 데이터 저장소, 설계 파일의 VBA가 배경에서 열고·쓰고·닫음
03어떻게 동작하는가
1
최종 코드 확보
MBD 자동생성 코드 또는 수기 작성된 펌웨어 탑재용 최종 C 코드를 대상으로 지정한다
2
AST 정적 파싱
libclang 기반 파서가 조건분기(if/switch/loop)와 전역/정적 변수 수정 내역을 추출한다
3
Black-box/White-box TC 도출
요구사항 기반 TC와 코드 기반 TC를 함께 도출한다
4
정합성 판정
두 TC를 대조해 Full_Match/Missing/Unspecified로 판정한다
5
검증 전용 파일 기록
판정 결과를 설계 템플릿과 별도인 검증 전용 파일에 기록해 V-Cycle 산출물로 남긴다
04Mode A(설계) vs Mode B(검증)
구분
Mode A — SW 로직 설계 (037)
Mode B — SW 테스트케이스 설계 (이번)
대상 코드
설계 단계에서 새로 도출된 후보 코드
펌웨어 탑재용 최종 코드 (MBD 자동생성/수기)
분석 방식
LLM이 코드를 직접 해석 (경량)
libclang 기반 실제 AST 정적 파싱
저장 위치
swDev_template_v1.xlsm (설계 SSoT)
swTC_template_v1.xlsx (검증 전용, VBA 없음)
산출물 성격
테스트케이스 초안 (draft)
V-Cycle 검증 산출물 (정식)
두 파일은 함수 정의(설계 템플릿)를 공용으로 쓰되, 검증 결과는 절대 같은 파일에 섞이지 않고 별도 파일의 Traceability_Matrix로 기록된다.
05Before / After
이전 — 설계 초안 TC로만 검증 계획
최종 코드 기준 확인 불가
설계 단계 LLM 해석 기반 TC(draft)만으로는 실제 최종 코드 기준 검증 여부를 확인할 수 없었다.
현재 — 최종 코드 AST 기반 정식 검증
설계 초안과 대조까지 완료
펌웨어 탑재용 최종 코드를 실제 AST로 파싱해 최소 테스트케이스를 제안하고, 설계 초안과 대조해 적정성까지 확인한다.
06기대 효과
최종 코드 기준 검증 확보
설계 단계가 아니라 실제 탑재 코드를 기준으로 최소 테스트케이스를 확보한다
설계-검증 산출물 명확히 분리
검증 결과가 별도 파일에 남아 V-Cycle 산출물로 바로 활용된다
설계 TC의 적정성 점검
설계 단계 TC(draft)와 대조해 부족하거나 과한 부분을 확인할 수 있다
실제 AST 파서로 정확도 향상
설계 단계(Mode A)의 향후 과제였던 실제 AST 파서 도입을 구현했다
07유의할 점
  • 검증 전용 파일에는 VBA 매크로가 전혀 없으며, 기록은 설계 파일의 VBA가 배경에서 열고·쓰고·닫는 방식으로만 이뤄진다
  • 검증 전용 파일이 없으면 자동으로 생성하고 시트 서식을 초기화하는 자가치유(Self-Healing) 기능이 있다
  • 기존 파이썬/VBA 모듈은 대부분 수정 없이 그대로 재사용되며, 신규 기능은 기존 모듈 맨 아래에 서브루틴을 추가하는 방식으로 덧붙여져 기존 코드를 보존한다
