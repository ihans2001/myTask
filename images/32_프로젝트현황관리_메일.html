프로젝트 현황관리 (메일 톤앤매너·아카이빙)

비정형성 메일을 정형화하여 업무 현황으로 관리한다. 로깅·아카이빙·분석 3개 축이 하나의 런처로 통합되며, 분석 과정의 톤/매너 판정은 개발 이슈·변경관리로 연계된다. LLM 이용/미이용 두 버전 중 LLM 이용 버전이 정확성 관점에서 우수하다.
Header-Run 가상스레드 분리 Delta 분석(중복제거) LLM 3-Tier Fallback
01왜 필요한가
최고의 기록이 매번 지적받음
메일은 가장 정직한 업무 기록이지만 비정형이라 Audit 때마다 정리 미흡 지적을 받는다
스레드 안에 이력이 뒤섞임
회신에 회신이 거듭된 메일 안에 과거 교신이 통째로 인용되어 있어도 분리할 도구가 없다
톤/분위기 변화를 정량화 못함
격양·에스컬레이션 같은 리스크 신호를 정성적으로만 느낄 뿐 추적할 방법이 없다
로깅·아카이빙·분석이 제각각
메일을 저장하고, 백업하고, 분석하는 작업이 각각 흩어져 있으면 관리가 번거롭다
02무엇을 만드는가
①
메일 로깅·아카이빙·분석 통합 런처
Outlook 메일 저장, 계정별/전체 아카이브 병합, 주간·기간별 통계 분석을 하나의 메뉴에서 실행한다
②
Header-Run 가상 스레드 분리
본문에 인용된 과거 교신 헤더를 파싱해, 전달(Forward)로 끊긴 대화도 온전히 재구성한다
③
톤앤매너·리스크 분석 → 개발이슈 연계
AI가 톤/요약/추이를 분석해 격양·에스컬레이션 신호를 리스크·이슈 관리로 연결한다
④
LLM 이용/미이용 2가지 버전
AI 기반 분석(정확도 우수)과 외부 전송 없는 키워드 기반 분석 중 상황에 따라 선택한다
핵심 원리
Delta 분석으로 이미 기록된 교신은 재분석하지 않고 신규분만 선별해 대장을 항상 SSoT로 유지
LLM Fallback
Claude 3.5 Sonnet → Gemini 1.5 Pro → GPT-4o 순차 전환으로 특정 API 장애에도 연속성 보장
03어떻게 동작하는가
1
대상 메일 선택(휴먼 트리거)
PM·리더가 중요하다고 판단한 메일을 직접 선택해 분석을 실행한다
2
가상 스레드 분리
Header-Run 알고리즘으로 본문 속 과거 교신을 개별 메일 단위로 분리한다
3
Delta 선별
관리대장의 최종교신시각과 비교해 신규 교신분만 골라낸다
4
톤앤매너 분석
LLM(또는 키워드 기반)이 톤/요약/이미지 정황을 분석한다
5
SEQ 이력 기록
SEQ-0001(신규)/SEQ-0001-1(후속) 체계로 관리대장에 누적 기록한다
6
리포트 저장·확인
최종 리포트를 바탕화면에 저장하고 메모장으로 즉시 확인한다
04AI 분석 vs 키워드 기반 분석
구분
AI 기반 분석 (권장)
키워드/부정어 기반 자체 분석 (대안)
정확도
문맥·뉘앙스까지 이해, 가장 높음
사전 정의 키워드·부정어 처리 기반
외부 전송
메일 원문·이미지가 외부 LLM으로 전송됨
외부 전송 없이 Outlook VBA 내에서 완결
전환 방식
기본 권장 옵션
보안 우려 시 옵션 설정만으로 즉시 전환
메일·JIRA·Teams는 파이프라인 뒷부분(LLM 분석~대장기록~SEQ 이력~리포트 출력)을 완전히 동일한 코드로 공유하며, 앞부분(트리거~파싱~Delta 판정)만 소스별로 차별화된다.
05Before / After
이전 — 감사 때마다 지적받는 메일
흐름 재구성에 수작업 대조
비정형 메일 더미에서 흐름을 재구성하려면 다수 메일을 수작업으로 대조해야 했다.
현재 — 정형화된 실록형 관리대장
가장 신뢰할 수 있는 업무 증적
톤앤매너·요약·리스크가 SEQ 체계로 누적되어 가장 신뢰할 수 있는 업무 증적이 된다.
06기대 효과
Audit 대응력 강화
정형화된 관리대장이 최고 수준의 감사 증거로 활용된다
리스크 조기 포착
톤 변화·에스컬레이션 신호가 리스크·이슈 관리로 자연스럽게 연결된다
중복 없는 SSoT 유지
Delta 분석으로 같은 내용을 반복 분석·중복 기록하지 않는다
보안 상황별 유연 대응
LLM 외부전송이 우려되면 키워드 기반으로 즉시 전환할 수 있다
07유의할 점
  • 자동 수신 트리거는 채택하지 않았다 — 일상 메일까지 전량 분석되면 노이즈에 리스크 신호가 묻히므로, 업무를 아는 사람이 직접 선택하는 휴먼 트리거를 원칙으로 한다
  • 메일 원문·이미지를 외부 클라우드 LLM으로 전송하므로, 정보보안팀 사전 승인 없이 R&D 교신 원문을 외부로 보내면 안 된다
  • Outlook Conversation API의 ConversationID는 메일이 전달(Forward)되면 연결이 끊기므로, Header-Run 알고리즘이 이를 대체한다
