프로젝트 종결보고서 자동화

연간 수십 건씩 종결되는 프로젝트마다 개별 양식으로 작성되던 종결보고서를, 계획서와 매칭되는 구조로 자동화한다. 계획은 프로젝트계획서에서 인용하고, 실적만 엑셀에 입력하면 표준 PPT로 자동 변환된다.
계획/실적 이원 토큰 계획값 자동 승계 3단계 팀승인+스폰서 최종승인
01왜 필요한가
연간 수십 건의 종결 보고서
신규계약 약 50건·진행중 약 200여개 규모에서 매번 개별 양식으로 작성하면 비효율이 크다
계획 대비 실적 비교가 빠지기 쉬움
종결보고서마다 계획값을 다시 옮겨 적으면 오탈자·불일치가 생긴다
실적 미기재 상태로 성급히 승인될 위험
검증 없이 승인되면 부실한 종결 근거가 남는다
Lessons Learned가 흩어짐
프로젝트마다 제각각 남기면 차기 프로젝트로 지식이 이어지지 않는다
02무엇을 만드는가
①
계획/실적 이원 토큰 체계
모든 정량 지표를 _plan(자동승계)/_actual(수동입력) 쌍으로 관리한다
②
계획값 자동 승계
기존 프로젝트계획서_template.xlsm을 선택하면 식별정보·일정·예산·품질게이트 계획값이 자동으로 채워진다
③
엑셀 수기 작성 → PPT 자동 변환
실적만 엑셀에 입력하면 계획서와 동일한 엔진으로 표준 PPT가 생성된다
④
팀 3단계 승인 + 스폰서 최종승인
Draft→검토중→승인은 프로젝트 수행팀이 진행하고, 종결보고서 전체 최종승인은 스폰서(또는 상위 보직자)가 수행한다
핵심 원리
config.py와 동일한 엔진(구역정의→토큰/표/첨부 매핑→검증→생성)을 재사용, config_closure.py만 신설
승계 원칙
"_actual" 접미사 토큰은 BASELINE_MAP에서 절대 제외 — 수동 입력 원칙
03어떻게 동작하는가
1
종결보고서 생성
config_closure.py 정의에 따라 종결보고서_template.xlsm(16개 시트)을 생성한다
2
계획값 자동 승계
기존 계획서 xlsm을 선택하면 식별정보 6건+계획값 20건이 자동으로 채워진다
3
실적 수기 입력
담당자가 실적(_actual) 값과 가변표를 엑셀에 직접 입력한다
4
팀 내 3단계 승인
Draft→검토중→승인 스탬프를 프로젝트 수행팀이 진행하며, 실적 미기재 시 검증 단계에서 경고한다
5
PPT 생성 및 스폰서 최종승인
계획서와 같은 엔진으로 표준 PPT를 생성하고, 스폰서(상위 보직자)가 전체 문서를 최종 승인한다
04프로젝트계획서 vs 종결보고서
구분
프로젝트계획서
종결보고서 (이번)
목적
앞으로 할 일을 선언
실제 한 일을 정산·평가
핵심 데이터
H열 '내용' 단일
계획(_plan, 자동승계) / 실적(_actual, 수동입력) 이원화
승인 체계
v1~v6 (마일스톤 게이트별)
Draft→검토중→승인(팀, 3단계) + 스폰서 최종승인
작성 방식
사람이 직접 입력
계획값은 자동 승계, 실적만 입력
계획서용 pipeline.py를 import 문 한 줄만 바꿔 pipeline_closure.py로 재사용했으며, 최종 검증에서 미작성 플레이스홀더·미연결 가변표 0건으로 구조적 정합성을 확인했다.
05Before / After
이전 — 프로젝트마다 개별 양식
종결 근거의 편차가 큼
종결보고서를 담당자가 개별 양식으로 작성해 품질/안전/보안 종결 근거와 Lessons Learned 축적이 프로젝트마다 편차가 컸다.
현재 — 계획서 엔진 재사용 자동화
승인 체계까지 구조화
계획값은 자동 승계되고 실적만 입력하면 표준 PPT로 통일되어, 팀 승인과 스폰서 최종승인까지 구조화된다.
06기대 효과
반복 작업 대폭 절감
연간 수십 건의 종결보고서 작성 부담을 계획서 자동화 인프라 재사용으로 줄인다
계획값 불일치 제거
자동 승계로 오탈자·재입력 리스크를 없앤다
성급한 승인 차단
실적 미기재 상태에서는 검증 단계가 경고해 부실 승인을 막는다
지식 인계 품질 향상
Lessons Learned와 미해결 이슈 인계가 구조화되어 차기 프로젝트·유지보수 조직에 전달된다
07유의할 점
  • "_actual" 접미사 토큰은 자동 승계 대상에서 절대 제외되며, 반드시 담당자가 직접 입력해야 한다 (합의된 원칙)
  • 한 슬라이드에 가변표가 2개 이상 있으면 자동분할이 적용되지 않는 구조적 한계가 있어, Outsourcing Closure처럼 가변표 1개씩 갖는 구역으로 분리해야 한다
  • 프로젝트명이 계획서와 종결보고서 간에 일치하지 않으면 경고 후 계속 진행되므로, 담당자가 직접 확인해야 한다
