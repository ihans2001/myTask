엑셀 취합 + 파워포인트 회의자료 자동변환

여러 개별 엑셀 자료를 하나의 테이블로 취합한 뒤, config 기반 파이프라인으로 파워포인트 회의자료를 자동 생성한다. 자료 작성 이력이 엑셀로 남아 변천 과정을 그대로 추적할 수 있다.
config 기반 변환 병합셀·임베디드 개체 재현 오버플로우 자동 슬라이드 분할
01왜 필요한가
셀 단위 복사·붙여넣기 의존
엑셀 표를 파워포인트로 옮길 때 셀 단위 복사·붙여넣기에 의존해 시간이 오래 걸리고 작업이 자주 끊긴다
병합 셀 재현이 어려움
가로·세로 병합이 있는 표는 옮기는 과정에서 병합 상태가 깨지기 쉽다
행이 넘치면 수작업 분할
표준양식 한 장에 담기지 않는 표는 슬라이드를 수동으로 나눠야 한다
삽입 개체는 옮기기 더 어려움
엑셀 셀에 들어있는 이미지나 임베디드 개체는 그대로 옮기기 까다롭다
02무엇을 만드는가
①
엑셀 개별자료 취합
여러 개별 엑셀 자료를 하나의 테이블로 취합해 관리한다
②
config 기반 PPT 자동 생성
엑셀 데이터를 일괄 추출해 PPT 표준양식에 값만 교체해 이식한다
③
병합 셀·오버플로우 처리
가로·세로 병합을 실제로 재현하고, 행이 넘치면 병합을 지키며 슬라이드를 자동 분할한다
④
임베디드 개체 재임베딩
셀 속 이미지·개체를 더블클릭으로 원본이 열리는 진짜 임베디드 형태로 재삽입한다
핵심 원리
모범 표 XML을 deepcopy해 텍스트만 교체 — 서식 손실이 구조적으로 불가능
실행 환경
표 생성은 OS 무관(Python) 개체 재임베딩만 Windows+PowerPoint COM 필요
03어떻게 동작하는가
1
엑셀 일괄 추출
시트별 규칙에 따라 표 데이터·병합 범위·개체 앵커 좌표를 한 번에 로드한다
2
표 서식 복제
모범 표 XML을 복제해 텍스트만 교체한다
3
병합 셀 재현
gridSpan/rowSpan/hMerge/vMerge를 적용해 가로·세로 병합을 실제로 재현한다
4
오버플로우 분할
병합이 잘리지 않는 안전한 경계에서 슬라이드를 자동 복제한다
5
개체 재임베딩
Windows에서 AddOLEObject로 클립보드 없이 원본 개체를 직접 삽입한다
04Word 변환 시스템과의 비교
구분
Word 변환 시스템
PowerPoint 변환 시스템 (이번)
문서 구조 단위
챕터/절 (최대 4단계)
슬라이드 1장 = 조직·과제·주제 1건
병합 셀 처리
헤더 병합만 자동확장
표 안 가로+세로 병합을 실제로 재현
오버플로우 처리
Word가 자동 개행
슬라이드는 자동 개행 없어 직접 계산
실행 환경
OS 무관
표 생성은 무관, 재임베딩은 Windows 필수
클립보드를 거치지 않는 AddOLEObject(FileName:) 방식을 채택해, 기존 셀 단위 붙여넣기의 고질적 병목(포맷 협상, 반복 모달창)을 구조적으로 제거했다.
05Before / After
이전 — 고정양식 PPT 직접 작성
셀 단위로 옮겨 적어 시간 소요
정형화된 파워포인트 양식을 매번 셀 단위로 옮겨 적어 작성 시간이 오래 걸렸다.
현재 — 엑셀 작성 후 자동 변환
MH 절감 + 이력 관리
엑셀로 작성하고 자동 변환해 회의자료 작성 MH를 절감하고, 작성 이력도 엑셀로 남는다.
06기대 효과
회의자료 작성 MH 절감
셀 단위 복사·붙여넣기 대신 일괄 추출·생성으로 처리한다
변천 과정 모니터링
자료 작성 이력이 엑셀로 관리되어 내용 변화를 추적할 수 있다
서식 손실 없음
모범 표 XML을 그대로 복제해 서식이 그대로 유지된다
이행 실적으로 확대
이력 관리를 기반으로 이행 실적 관리까지 확장할 수 있다
07유의할 점
  • 개체 재임베딩(AddOLEObject)은 Windows+PowerPoint 환경에서만 동작하며, 표 생성 자체는 OS와 무관하다
  • 세로 병합이 분할 경계에 걸치면 병합이 끝나는 행까지 강제로 포함시켜, 기준 행 수를 다소 넘기더라도 병합 무결성을 우선한다
  • 설정값(SHEET_CONFIGS)이 아직 코드에 하드코딩되어 있어, Word 시스템처럼 config.py로 분리하는 작업이 향후 과제로 남아있다
