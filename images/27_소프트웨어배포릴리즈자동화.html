IHANS-PRO-2026-027 2026-09-10 가이드

소프트웨어 배포 릴리즈 자동화

SW BOM을 이용해 릴리즈 노트를 작성하는 등 체계적인 배포 관리로 정합성을 확보한다. 클라우드 서버 없이도 빌드 완료 후 검증·노트 작성·메일 발송까지 자동화하고, 배포 시점의 스냅샷을 남겨 오딧에 대비한다.
VBA-Python 브릿지 Draft 검증 필수(★★ 경고) 스냅샷 ZIP + SHA-256
01왜 필요한가
배포 정합성 확보 필요
릴리즈 노트 내용이 실제 산출물과 일치해야 하는데 수작업으로는 누락되기 쉽다
클라우드 없이도 자동화 필요
클라우드 서버 없이 로컬 환경만으로 검증부터 메일 발송까지 이어져야 한다
배포 시점 증적 필요
나중에 오딧이 들어오면 그 시점의 정확한 산출물 상태를 보여줘야 한다
미비 데이터가 조용히 묻힘
연동 안 된 값이나 기본값이 그대로 릴리즈 노트에 들어가면 알아채기 어렵다
02무엇을 만드는가
①
SW BOM 기반 릴리즈 노트 자동 작성
SSoT 마스터의 인스턴스_통합 시트를 파싱해 고객 제출용 릴리즈 노트를 작성한다
②
미비 데이터 자동 경고
API 미연동·기본값 적용 등 정합성이 의심되는 항목에 ★★ 표식을 자동으로 남긴다
③
배포 시점 스냅샷 확보
빌드 산출물을 ZIP으로 묶고 진짜 SHA-256 해시를 계산해 릴리즈 노트에 주입한다
④
Draft 검증 후 최종 확정
파일명에 _draft를 강제 부여해 연구원의 수기 검토를 거치도록 한다
핵심 원리
스냅샷 ZIP을 먼저 만들고 그 진짜 해시를 노트에 역주입(선 압축, 후 주입)
문서 변환
환경에 따라 Word COM / Pandoc / Pandoc+LibreOffice 중 선택해 .docx·.pdf 생성
03어떻게 동작하는가
1
외부 데이터 동기화
Codebeamer/Jira/Git/SVN 등에서 릴리즈 메타데이터를 수집해 JSON 캐시로 저장한다
2
Draft 릴리즈 노트 작성
인스턴스_통합 시트를 파싱해 _draft가 붙은 검토용 노트를 생성한다
3
연구원 수기 검토
Draft 파일을 검토하고 ★★ 표식이 붙은 항목을 확인·보완한다
4
스냅샷 압축·해시 계산
빌드 산출물을 ZIP으로 묶고 SHA-256 해시를 계산한다
5
진짜 해시 주입 및 최종 문서 생성
계산된 해시를 노트에 반영하고 .docx로 변환한다
6
SSoT 마스터 기록
스냅샷 경로와 해시를 SSoT 마스터의 스냅샷_보관 시트에 기록한다
04문서 변환 방식 비교
구분
Word COM (초기버전)
Pandoc 단독 / Pandoc+LibreOffice (현재)
변환 방식
Word 애플리케이션 직접 호출
Pandoc(md→docx), 필요 시 LibreOffice(docx→pdf) 추가
안정성
대화상자·좀비 프로세스 위험
대화상자 없이 배치 변환, 안정적
SSoT 저장 방식
openpyxl로 xlsm 직접 저장
xlwings로 실제 엑셀을 구동해 저장
openpyxl로 xlsm을 직접 열어 저장하면 VBA 매크로가 손상될 위험이 있어, 이후 버전은 xlwings로 실제 엑셀을 구동해 저장하는 방식으로 교체했다.
05Before / After
이전 — 수작업 릴리즈 노트 작성
누락·오기 위험 상존
산출물 해시나 CR 이력을 사람이 직접 옮겨 적어 누락·오기 위험이 있었다.
현재 — SW BOM 기반 자동 작성+검증
미비 항목을 표시하고 검토 후 확정
SSoT 데이터를 자동 집계하고 미비 항목은 ★★로 표시해, 검토 후 확정하는 구조로 정합성을 확보한다.
06기대 효과
배포 정합성 확보
SW BOM 기반으로 릴리즈 노트를 작성해 산출물과 문서가 어긋나지 않는다
미비 데이터 즉시 식별
★★ 표식으로 검증되지 않은 항목을 놓치지 않는다
오딧 대비
배포 시점 스냅샷과 SHA-256 해시로 그 시점 상태를 증명할 수 있다
로컬 환경 완결
클라우드 서버 없이도 검증부터 노트 작성까지 자동화할 수 있다
07유의할 점
  • openpyxl로 xlsm 마스터를 직접 열어 저장하면 VBA 매크로가 손상될 수 있어, SSoT 마스터 저장은 반드시 xlwings 방식을 사용해야 한다
  • Draft 파일명에는 _draft가 강제로 부여되므로, 연구원의 수기 검토를 거치기 전까지는 최종본으로 취급하지 않는다
  • 진짜 해시는 스냅샷 압축 이후에만 계산 가능하므로, 노트 초안 작성 시점의 해시는 임시값이며 최종 단계에서 실제 값으로 교체된다
