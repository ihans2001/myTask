설계~구현 시퀀스 다이어그램 Diff 자동화

설계 의도와 실제 코드가 시간이 지나며 벌어지는 드리프트(Drift)를, 사람이 전수 비교하지 않고도 자동으로 드러낸다. 설계 단계의 플로우차트와 코드 기반 다이어그램을 각각 자동 생성해 구조 단위로 비교한다.
설계-구현 정합성 자동검증 폴더 전체 배치 처리 PlantUML 표준 형식
01왜 필요한가
설계 문서가 코드 변경을 못 따라감
설계 시점에 한 번 그려진 다이어그램이 이후 코드 변경사항을 반영하지 못한다
드리프트가 안전·보안 분석에 영향
설계와 구현의 괴리는 추적성 훼손과 영향도 분석 오류로 이어진다
소급 보완 작업이 방대함
뒤늦게 아키텍처 문서를 실제 구현 기준으로 맞추는 작업에 많은 시간이 든다
전체를 다 그리면 아무도 안 읽음
수백~수천 개 함수를 전부 그리면 정작 중요한 것이 묻힌다
02무엇을 만드는가
①
설계 시퀀스 다이어그램(초안)
설계단계 플로우차트 테이블을 PlantUML로 자동 변환
②
구현 시퀀스 다이어그램(As-built)
폴더 내 전체 코드를 스캔해 실제 구현 기준으로 자동 생성
③
설계-구현 정합성 리포트
참가자·분기구조·메시지 순서 차이를 구조 단위로 자동 비교
④
배치(batch) 처리
폴더에 저장된 모든 코드에 대해 한 번에 수행 가능
핵심 기술
AST(추상구문트리) 기반 자동 추출 프로젝트 심볼 인덱스(콜그래프) 구조화 모델로 변환 후 의미 단위 Diff
3단계 흐름
① 설계(플로우차트 작성) ② 코딩완료(코드에서 자동 추출) ③ 비교분석(구조 Diff)
03왜 Sequence BOM이 꼭 필요한가
1타 파일 전역변수 소유관계 — 프로젝트 전체를 인덱싱해야 알 수 있다
2함수 콜의 실제 정의처 — 같은 파일/다른 파일/외부 라이브러리 중 어디인지 별도 확인 필요
3TaskTime(트리거 주기) — 보통 코드가 아니라 스케줄러 설정 파일에 있다
4UDN/고장모드 — 코드 안에 애초에 존재하지 않는, 엔지니어의 안전분석 판단
AST는 '구조적 사실'만 알려준다 — 위 4가지 '의미 정보'(Sequence BOM)는 계속 사람이 채워야 완전한 다이어그램이 완성된다.
04작도 대상 선정 — 왜 전체를 다 그리면 안 되는가
•문서 피로도 — 수백~수천 개 다이어그램은 정작 중요한 것을 묻히게 한다
•재사용 모듈 제외 — 변경 없는 검증된 모듈까지 매번 다시 그릴 필요 없다
•유지보수 비용 — 코드가 바뀔 때마다 갱신해야 하는 지속적 비용이다
•우선순위 — 신규개발·인터페이스 변경·안전/보안 critical 함수부터 그린다
O 함수가 내부에서 만나는 X 함수는 leaf 참가자로 표시하되, 반드시 '미전개(블랙박스)' 상태를 기록한다 — 안전하다고 확인된 것과 단순히 안 그린 것을 구분하기 위해서다.
05무엇을, 어디까지 비교하는가
비교 차원
비교 방법
자동화 가능 여부
① 참가자 집합
설계 vs 구현의 전역변수·호출함수 집합을 비교
완전 자동화
② 분기·루프 구조
조건/반복의 개수·중첩을 트리로 변환해 비교
구조는 자동, 조건식 의미는 사람 확인
③ 메시지 순서/방향
참가자별 Read/Write 순서를 위상 비교
완전 자동화
④ UDN/고장모드
그 방향에 도달하는 코드 경로 존재 여부만 확인
도달가능성만 자동, 타당성은 사람 판단
설계 단계에 명시적으로 기재된 항목만 비교 대상으로 삼는다 — 미기재 항목은 '비교불가(N/A)'로 분류해 오탐(노이즈)을 막는다.
06자동화 경계
완전 자동화
AST 파싱, 심볼 인덱스 구축, 콜그래프 추적, PlantUML 생성·렌더링, 설계-구현 구조적 Diff 계산
사람이 계속 담당
Sequence BOM 작성(참가자 그룹핑·UDN·TaskTime), 작도 대상 O/X 선정, 설계 플로우차트 테이블 작성, Diff 리포트의 최종 조치 판단
07기대 효과
드리프트를 전수검토 없이 탐지
설계와 구현 사이 어긋난 지점을 자동으로 드러낸다
명세서 소급 보완 부담 감소
코딩 완료 후 문서화 작업의 상당 부분이 자동화된다
숨은 결합을 조기에 발견
전역변수 공유·콜체인 확장을 미리 찾아 후속 안전·보안 분석 품질을 높인다
설계 후보안 비교에도 재사용
같은 Diff 엔진으로 여러 아키텍처 후보안을 정량 비교할 수 있다
08향후 진행 순서
  1. 프로젝트 폴더 스캔 + 전역 심볼 인덱스 빌드 스크립트 개발
  2. Sequence BOM 스키마 확정 및 샘플 1개 함수로 End-to-End 파이프라인 검증
  3. 실제 소스코드 엣지케이스(switch fallthrough, goto/label 등)에 대한 AST 변환 규칙 강건화
  4. 구조화 모델(중간표현) 스키마 설계 및 설계-구현 Diff 엔진 프로토타입 개발
  5. 여러 함수·콜체인으로 확대 적용, 자동화 배치(batch) 스크립트화
