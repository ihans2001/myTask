SW 통합검증 테스트케이스 설계 (SWE.5)

유닛(SWE.4) 테스트와는 접근방식이 다른 SW 통합검증(SWE.5) 테스트케이스를, SW 아키텍처링의 중간 산출물인 시퀀스 다이어그램 테이블을 편집 없이 그대로 활용해 자동 도출한다.
시퀀스 테이블 재사용 컴포넌트 내부→인터페이스 확장 Pre/Post+고장모드→TC description
01왜 필요한가
통합검증은 유닛검증과 접근방식이 다름
개별 함수 단위 검증(SWE.4)과 달리 호출 체인·이종 Task 간 신호전달을 봐야 한다
통합검증용 자료를 다시 만들면 이중작업
시퀀스 다이어그램을 위해 이미 만든 테이블이 있는데 통합검증용으로 따로 또 만들면 비효율적이다
컴포넌트 내부와 인터페이스 검증이 섞이기 쉬움
같은 컴포넌트 안의 호출과, 서로 다른 컴포넌트/Task 간 전달을 구분해서 봐야 한다
자동화로 다루기 어려운 거동이 있음
IG-OFF 거동처럼 자동화 로직만으로는 커버하기 어려운 부분이 있다
02무엇을 만드는가
①
시퀀스 다이어그램 테이블 그대로 재사용
유닛함수명을 실제 함수명과 동일하게 작성해둔 테이블을 편집 없이 통합검증 입력으로 사용한다
②
소스코드 폴더 순환 파싱
테이블의 유닛함수를 순환하며 소스코드 폴더에서 실제 입력·출력 변수를 파싱한다
③
컴포넌트 내부 → 인터페이스로 단계적 확장
Intra-Task(컴포넌트 내부 호출체인) 검증에서 Inter-Task(컴포넌트 간 신호전달) 검증으로 확장한다
④
Pre/Post+고장모드를 TC description으로 기록
시퀀스 테이블의 사전/사후조건과 SW 고장모드 정보를 테스트케이스 설명에 담아 검증 과정에서 참조한다
핵심 원리
Comma로 구분된 Task Time(예: 10ms, 100ms) 메타데이터로 이종 Task 경계를 자동 식별
자동화 한계 보완
IG-OFF 거동 등 자동화로 다루기 어려운 일부는 수기로 작성해 자동 도출 결과에 추가
03어떻게 동작하는가
1
시퀀스 테이블 확보
SW 아키텍처링 자동화의 중간 산출물인 시퀀스 다이어그램 테이블을 그대로 입력으로 쓴다
2
유닛함수 순환 파싱
테이블의 유닛함수명으로 소스코드 폴더를 순회하며 입력·출력 변수를 추출한다
3
Intra-Task TC 도출
같은 Task 안의 호출 체인 순서와 경계값을 검증하는 TC를 생성한다
4
Inter-Task TC 도출
Task Time이 다른 컴포넌트 간 신호·데이터 전달을 검증하는 TC를 생성한다
5
대조 판정 및 수기 보완
요구사항-TC-소스코드를 대조해 Full_Match/Missing/Unspecified로 판정하고, 자동화가 어려운 거동은 수기로 추가한다
04Intra-Task vs Inter-Task
구분
Intra-Task (컴포넌트 내부, SWE.5.ENG.1)
Inter-Task (컴포넌트 인터페이스, SWE.5.ENG.2)
검증 대상
같은 Task 안 유닛 간 호출 순서·경계값
서로 다른 Task(이종) 간 신호·데이터 전달
판단 근거
시퀀스 테이블의 호출체인(Level/Fname)
Comma 구분 Task Time 메타데이터로 경계 식별
산출물 예
"FS1_1→FS1_2→…→FS1_8 순서 보존" 검증
Task[S1]↔Task[100] 등 경계 신호 검증
기존 유닛검증 영역(ModeA/B_TC_Baseline, Traceability_Matrix)은 1%도 수정하지 않고 그대로 보존하며, 통합검증 전용 시트 3개만 신규로 추가된다.
05Before / After
이전 — 통합검증 자료를 별도로 준비
같은 정보를 두 번 정리
시퀀스 다이어그램용 테이블이 있는데도 통합검증 테스트케이스는 따로 다시 정리해야 했다.
현재 — 같은 테이블로 통합검증까지 확장
편집 없이 그대로 재사용
시퀀스 테이블을 편집 없이 그대로 재사용해 컴포넌트 내부부터 인터페이스까지 통합검증 TC를 도출한다.
06기대 효과
이중작업 제거
시퀀스 다이어그램용 테이블을 그대로 재사용해 통합검증 자료를 따로 만들지 않는다
검증 범위 단계적 확장
컴포넌트 내부에서 인터페이스까지 단계적으로 통합검증 범위를 넓힌다
검증 근거 자동 기록
Pre/Post·고장모드 정보가 TC description에 남아 검증 과정에서 바로 참조된다
자동화 사각지대 보완
IG-OFF 거동처럼 자동화가 어려운 부분은 수기로 채워 전체 커버리지를 확보한다
07유의할 점
  • 시퀀스 다이어그램 테이블의 유닛함수명은 반드시 실제 소스코드의 함수명과 동일하게 작성해야 입출력 변수 파싱이 정상 동작한다
  • 기존 유닛검증(SWE.4) 영역은 전혀 건드리지 않으며, 통합검증(SWE.5) 전용 시트만 별도로 추가되는 구조다
  • IG-OFF 거동 등 자동화 사각지대는 자동 도출 결과에 수기로 추가해야 하며, 자동화가 전부를 대체하지는 않는다
