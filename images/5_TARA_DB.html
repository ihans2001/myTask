TARA 결과 DB화 — 쿼리 + RAG 하이브리드

제어기별 TARA 결과를 하나의 데이터베이스에 누적하고, 정확한 조회(SQL)와 의미 기반 검색(RAG)을 결합한다. 과거 결과가 다음 TARA를 시작하는 출발점이 된다.
SQL + 벡터DB 하이브리드 28개 테이블 Full · Tier TARA 모두 지원
01왜 필요한가
매번 처음부터 다시 시작
과거 제어기의 분석 결과를 다시 찾아보기 어려워, 유사한 위협도 매번 새로 작성한다
결과가 파일마다 흩어짐
제어기별로 따로 저장된 워크북을 일일이 열어 넘나들며 비교해야 한다
판단 근거는 검색이 안 됨
"왜 이 등급을 선택했는지" 같은 서술형 설명은 키워드만으로 찾기 어렵다
현황 집계에 반복 수작업
특정 등급 이상 위협, 미결정 위험처리 등을 매번 손으로 추려야 한다
02무엇을 만드는가
①
통합 TARA 데이터베이스
모든 제어기·모든 결과서를 28개 테이블 하나의 DB에 누적
②
자동 적재 브릿지
TARA 워크북에서 매크로 하나만 실행하면 결과가 DB로 이동
③
대표 조회 8종
등급 이상 위협 조회, 위험처리 미결정 목록 등 자주 찾는 질문에 즉답
④
서술형 의미 검색(RAG)
판단 근거·설명 문장을 뜻으로 찾아내는 벡터 검색
이용 기술
SQL DB (로컬→서버 전환 가능) Chroma 벡터DB VBA-Python 브릿지
지원 범위
Full TARA·Tier TARA 하나의 DB에서 함께 관리 같은 결과서를 나중에 Tier→Full로 갱신 가능
03동작 흐름
1
TARA 수행
엔지니어가 워크북에서 매크로로 TARA를 수행한다
2
자동 호출
결과서 작성이 끝나면 매크로가 적재 프로그램을 자동으로 부른다
3
구조화 데이터 적재
등급·점수 같은 정형 필드는 SQL DB에 저장된다
4
서술형 데이터 임베딩
설명·판단근거 같은 문장은 벡터DB에 별도로 저장된다
5
조회 + 의미검색 결합
정확한 조회와 의미 기반 검색을 함께 활용해 다음 TARA 초안의 출발점으로 삼는다
04SQL + 벡터DB — 왜 둘 다 필요한가
SQL DB — 구조화 필드
등급·점수·판정결과처럼 정해진 값을 정확하게 저장한다. "이 조건에 맞는 것만 정확히 찾기"에 강하다.
예시 — 특정 등급 이상 위협 시나리오, 위험처리 미결정 목록, 제어기별 최신 결과서
Chroma 벡터DB — 서술형 텍스트
설명·판단근거 같은 자유 문장을 뜻으로 저장한다. "비슷한 의미를 찾기"에 강하다.
예시 — 과거 유사 판단 사례 검색, 비슷한 위협 서술 찾기
질의 라우터가 상황에 맞게 조합 — 정확한 숫자·목록이 필요하면 SQL 조회를, 비슷한 사례나 설명이 필요하면 벡터 검색을 사용한다. 두 저장소는 하나의 결과서에서 동시에 채워진다.

1기준문서
제어기별로 DB를 나누지 않는다 — 모든 제어기, 모든 TARA 결과서가 하나의 DB에 계속 누적되므로 제어기 간 비교와 이력 추적이 가능하다.
06기대 효과
다음 TARA의 출발점 확보
DB와 의미 검색으로 유사 사례를 찾아 초안 작성 시간을 줄인다
심사·현황 집계 즉시 가능
반복적으로 찾던 목록을 조회 한 번으로 확보한다
Full·Tier 이력을 함께 관리
정보가 나중에 채워져도 같은 결과서를 그대로 갱신할 수 있다
제어기 간 비교·추적 가능
모든 결과가 한 곳에 쌓여 제어기를 넘나든 분석이 가능하다
07유의할 점
  • 로컬 단계는 파일 하나(SQLite)로 충분하지만, 여러 사람이 동시에 쓰기 시작하면 서버 전환이 필요하다
  • 서술형 검색(RAG)의 임베딩 모델은 사내망 제한 환경을 고려해 대체 가능하도록 설계되어 있다
  • 구조를 변경하면 기존 테이블은 자동으로 바뀌지 않으므로 별도 반영 절차가 필요하다
