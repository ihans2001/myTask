SW 산출물 해시 생성 및 검증

고객이 제공한 원본 해시와 협력사 산출물의 해시를 자동으로 대조해 자료 무결성을 보장한다. CRA 대응을 위해 장기간 보관해야 하는 산출물 증적을 파일·엑셀 워크시트 단위로 남긴다.
VBA-Python 브릿지 4종 해시 알고리즘 자동감지 파일/워크시트 단위 검증
01왜 필요한가
CRA 대응 보관 의무
CRA(사이버보안법)에 의거해 자료 제출 후 향후 10년간 보관해야 할 필요성이 커지고 있다
원본 훼손 여부 확인
협력사에게 전달된 산출물이 고객이 제공한 원본과 정확히 같은지 확인할 방법이 필요하다
모든 형태의 파일을 다뤄야 함
바이너리·문서·압축파일 등 형식이 제각각인 산출물 전체에 동일한 방식을 적용해야 한다
엑셀은 파일 단위로 부족
워크북 안의 워크시트 하나만 바뀌어도 이를 잡아낼 수 있어야 한다
02무엇을 만드는가
①
해시 생성 (고객 제공)
AddFilesWithHashCalc 매크로가 원본 파일들의 해시를 일괄 계산한다
②
해시 검증 (협력사 검증)
ExecuteBatchHashVerification 매크로가 원본 해시와 대조해 PASS/FAIL을 판정한다
③
파일 단위 해시
64KB Chunk 스트리밍으로 대용량 바이너리도 메모리 부담 없이 처리한다
④
워크시트 단위 해시
엑셀은 "셀주소=값"으로 직렬화해 워크시트 단위로 해시를 계산한다
핵심 원리
MD5 / SHA1 / SHA256 / SHA512 — 기대 해시 길이로 알고리즘 자동감지
활용 예시
SW 배포 시 릴리즈 노트에 해시 주입 후 발송 릴리즈 자료 전체에 해시 적용 가능
03어떻게 동작하는가
1
원본 해시 계산
고객이 AddFilesWithHashCalc(mHashEach.bas)로 원본 파일의 해시를 계산한다
2
해시 포함 자료 전달
계산된 해시를 릴리즈 노트 등에 주입해 산출물과 함께 전달한다
3
협력사 해시 재계산
협력사가 ExecuteBatchHashVerification(mHashBatch.bas)로 동일 대상의 해시를 다시 계산한다
4
대조 및 판정
원본 해시와 자동으로 대조해 PASS/FAIL/N/A로 판정하고 기록한다
04파일 단위 vs 워크시트 단위
구분
파일_해시검증 시트
엑셀_워크시트_해시검증 시트
대상
모든 형태의 파일 (바이너리·문서·압축 등)
엑셀 워크북 내 특정 워크시트
계산 방식
64KB Chunk 스트리밍 해시
"셀주소=값" 직렬화 후 해시
용도
산출물 전체 무결성 확인
엑셀 내 특정 시트만 변경 여부 확인
워크시트 해시는 셀 좌표까지 포함해 계산되므로, 값이 이동하거나 행/열이 삽입·삭제되면 값이 같아도 다른 해시가 된다.
05Before / After
이전 — 육안·수작업 대조
파일을 열어 하나하나 비교
산출물이 여러 개면 각각 열어 눈으로 비교해야 해서 시간이 오래 걸리고 누락 위험이 있다.
현재 — 자동 일괄 대조
매크로 실행 한 번으로 전체 판정
엑셀에 파일 경로와 기대 해시만 채워두면, 매크로 실행 한 번으로 전체를 PASS/FAIL로 자동 판정한다.
06기대 효과
무결성 증적 확보
CRA 대응을 위한 장기 보관용 해시 증적을 자동으로 생성한다
변조 즉시 감지
원본과 한 글자만 달라도 해시가 달라져 즉시 식별된다
모든 파일 형식 지원
바이너리·문서·압축 등 형식 제약 없이 동일하게 적용된다
워크시트 단위 정밀 검증
엑셀 파일 전체가 아니라 시트 단위로도 변경 여부를 확인할 수 있다
07유의할 점
  • 워크시트 해시는 셀 좌표까지 포함하므로, 값이 같아도 위치가 바뀌면 해시가 달라진다
  • 알고리즘은 기대 해시 문자열의 길이(32/40/64/128자)로 자동 판별되므로, 기대 해시를 정확히 입력해야 한다
  • verify_hash_batch.py는 verify_hash_each.py와 반드시 같은 폴더에 있어야 워크시트 검증 모드가 동작한다
