SR지향 추적성 자동검증

V-모델 단계마다의 양방향 추적성 데이터는 그대로 두고, 그 데이터로부터 고객요구조건(CR)까지의 다단계 추적성을 자동으로 계산한다. 팬아웃·오르판·다이아몬드 같은, 인접 단계만 봐서는 보이지 않던 오류까지 찾아낸다.
V-모델 전 단계 연결 그래프 기반 자동계산 CR 검증완료 여부 즉답
01왜 필요한가
인접 단계 커버리지만으로는 부족
A-B, B-C가 각각 100%여도 최종 체인은 끊겨 있을 수 있다
분기·합류가 섞이면 역추적이 폭발
하나의 요구조건이 여러 항목으로 갈라졌다 다시 합쳐지는 구조는 사람이 손으로 추적하기 어렵다
심사 질문에 즉답이 어려움
"이 요구조건이 검증까지 끝났는가"를 물으면 매번 수작업 역추적이 필요하다
기존 도구의 결과도 검증되지 않음
팬아웃·다이아몬드가 섞인 예외 상황에서 기존 추적 도구가 부정확한 결과를 낼 수 있다
02무엇을 만드는가
①
다단계 추적성 자동계산 엔진
인접 단계 링크만으로 CR부터 임의 하위 단계까지의 연결을 계산
②
추적성 오류 자동 탐지
팬아웃·오르판·다이아몬드·순환참조를 계산 과정에서 함께 검출
③
스냅샷 기반 검증 리포트
마일스톤 시점마다 그 시점 기준으로 항상 일관된 결과를 산출
④
교차검증 수단
기존 추적 도구의 결과가 정확한지 독립적으로 대조
핵심 기술
그래프(인접 리스트) 기반 데이터 모델 그래프 순회(폐쇄, Closure) 연산 스냅샷 방식 검증
가상 데이터 검증 규모
노드 710개 · 엣지 674개 처리시간 0.46초 테스트케이스 33개 전건 통과
03V-모델 단계별 추적성
1
고객요구조건(CR)
제어기 개발에 반영할 항목을 식별한다
2
시스템 아키텍처
CR을 시스템 요소로 구체화한다
3
SW 아키텍처
시스템 요소를 SW 구조로 구체화한다
4
SW 상세설계
SW 구조를 함수 단위로 구체화한다
5
단위 함수 설계
최종 구현 단위까지 연결한다
각 단계는 대응하는 검증계획(시스템/SW통합/상세설계/단위 검증)과도 연결되어야 한다 — 추적성 연결의 최종 목적은 "CR이 정확히 구현되어 검증까지 완료되었는가"를 확인하는 것이다.
04무엇이 다른가 — 인접 추적성 vs 다단계 추적성
기존 — 인접 단계 추적성
A-B, B-C 각각의 연결 %만 확인
인접한 두 단계 사이의 커버리지는 보여주지만, 최종 목적지까지 체인이 끊기지 않고 이어지는지는 보여주지 못한다.
신규 — 다단계 추적성
A-B, B-C는 그대로 두고 A-C, A-D를 계산
인접 링크 데이터를 원본으로 유지한 채, CR부터 임의 하위 단계까지의 관계를 그래프 계산으로 자동 도출해 체인 전체의 무결성을 확인한다.
05자동 탐지되는 추적성 오류
Fanout (팬아웃)
상위 노드 1개가 하위 노드 여러 개로 갈라지는 것
Orphan (오르판)
상위로 거슬러 올라갈 부모 링크가 없는 노드
Diamond (다이아몬드)
갈라졌다가(팬아웃) 다시 한 노드로 합쳐지는 것
Cycle (순환참조)
A→B→C→A처럼 원을 그리며 되돌아오는 링크 구조
이 외에도 레벨 오매칭·중복·자기참조·댕글링 참조 등 데이터 품질 이슈 9종을 그래프 구성 전 단계에서 자동으로 걸러내고 로그로 남긴다.
06도입 로드맵
Phase 1
소규모 파일럿
CR 1~2개 체인만 export해 실데이터로 검증 로직을 실증한다
Phase 2
전체 규모 확장
프로젝트 전체 규모로 확대해 실데이터 품질이슈를 실측한다
Phase 3
API 자동화
수작업 export 단계를 없애고 완전 자동화 파이프라인을 구축한다
Phase 4
정례 운영
마일스톤별 스냅샷 검증을 정례화하고 심사 대응 자료로 축적한다
07기대 효과
심사 질문에 즉시 답변
"CR이 검증까지 완료됐는가"를 스냅샷마다 자동으로 산출한다
체인 단절을 자동으로 가시화
인접 %만으로는 안 보이던 끊김·오르판·다중소유를 찾아낸다
기존 도구의 정확성 교차검증
예외 상황에서도 다른 결과가 나오는지 독립적으로 대조한다
데이터 오류를 사람보다 먼저 발견
오탈자·레벨오매칭·중복 등을 자동으로 선별한다
08유의할 점
  • 현재까지는 가상 데이터로 검증이 완료된 상태(33개 테스트케이스 전건 통과)이며, 실제 데이터 적용은 소규모 파일럿부터 단계적으로 진행한다
  • 마일스톤 시점의 스냅샷 기준으로 계산하므로, 스냅샷 사이의 변경은 다음 스냅샷에서 반영된다
  • 팬아웃·다이아몬드 구조가 매우 드문 프로젝트에서는 효과가 제한적일 수 있다
